.. _ug:cha:802154:

The 802.15.4 Model
==================

.. _ug:sec:802154:overview:

Overview
--------

IEEE 802.15.4 is a technical standard that defines the operation of low-rate
wireless personal area networks (LR-WPANs). IEEE 802.15.4 was designed for data
rates of 250 kbit/s or lower to achieve long battery life (months or even years)
and very low complexity. The standard specifies the physical layer and media
access control.

IEEE 802.15.4 is the basis for the :protocol:`ZigBee`, :protocol:`ISA100.11a`,
:protocol:`WirelessHART`, :protocol:`MiWi`, :protocol:`SNAP`, and the
:protocol:`Thread` specifications, each of which further extends the standard by
developing the upper layers that are not defined in IEEE 802.15.4.
Alternatively, it can be used with :protocol:`6LoWPAN`, the technology used to
deliver IPv6 over WPANs, in order to define the upper layers. (Thread is also
6LoWPAN-based.)

INET provides a selected unsecured legacy-frame O-QPSK profile derived from
IEEE Std 802.15.4-2024, alongside explicitly retained legacy narrowband and UWB
models. This profile is not whole-standard support.

.. _ug:sec:802154:network-interfaces:

Network Interfaces
------------------

The native :ned:`Ieee802154NarrowbandInterface` and its explicit equivalent
:ned:`Ieee802154StandardInterface` use full EUI-64 or short addresses, a typed
MCPS/MLME service surface, complete MPDUs and FCS, and a packet-level O-QPSK PHY.
Each interface supplies a unique locally administered EUI-64 from its simulator
component ID. Set an explicit identity when it must remain stable across topology
changes:

.. code-block:: ini

   **.wlan[0].typename = "Ieee802154NarrowbandInterface"
   *.device.wlan[0].extendedAddress = "extended:02-01-12-34-56-78-9A-BC"

Call the native service provider or attach an ``Ieee802154MacDataReq`` packet
tag before sending an opaque MSDU to the upper gate. The adapter returns native
admission, confirmation and receive tags. It does not adapt generic 48-bit
``MacAddress``/ARP traffic, so an ordinary IP application needs an explicit
upper-layer adaptation. Receiver-side ``upperProtocol`` can select one known
protocol; no protocol identifier is carried in the MAC frame.

The complete MPDU must fit 127 bytes, including its variable native header and
FCS. There is no fixed MSDU MTU or automatic fragmentation. Idle reception is
disabled by default; enable ``rxOnWhenIdle`` or request scheduled receiver
windows through management when the device must listen.

:ned:`Ieee802154LegacyNarrowbandInterface` retains the old narrowband queue,
48-bit upper-layer contract and wire representation. Existing IPv4 showcases
select it explicitly. It is deprecated for the INET 5.0 cutover and retained
until at least 6.0. :ned:`Ieee802154UwbIrInterface` retains the separate legacy
UWB-IR model. Legacy and native narrowband frames are wire-incompatible.

.. _ug:sec:802154:physical-layer:

Physical Layer
--------------

The native composition uses :ned:`Ieee802154StandardRadio` and
:ned:`Ieee802154PhyService` with scalar signal representation, 2.4-GHz channels
11 through 26, 250 kbit/s and 16-us symbols. PHY services own turnaround,
timed CCA Mode 1, ED and transmit completion. ED and LQI mappings are documented
simulation choices with saturation, not hardware RSSI/LQI calibration.

The inherited BER curve and independent-bit error model are calculation
abstractions. Preamble acquisition probability, chip waveforms, oscillator
effects and calibrated hardware PER are not modeled. A locally canceled
transmission cannot retract a waveform already emitted by the shared medium.

Legacy narrowband radio types remain available for legacy compositions.
:ned:`Ieee802154UwbIrRadio` uses :ned:`Ieee802154UwbIrRadioMedium`; retention of
that model does not imply modern UWB support in the native profile.

.. _ug:sec:802154:mac-protocol:

MAC Protocol
------------

:ned:`Ieee802154StandardMac` owns the native PIB, unslotted CSMA/CA, receive
filtering, real immediate ACKs, direct retries, device-wide DSN and interframe
spacing. Retries retain their DSN. Duplicate suppression is disabled. Security
transforms are unsupported; protected input never becomes plaintext DATA.

With ``enableManagement=true`` and a bound management client, the profile adds
non-beacon START, active/passive/ED/orphan scans, discovery-response beacons,
association and disassociation, indirect DATA/POLL/PURGE, orphan realignment,
PAN-conflict notifications and scheduled receiver control. PAN selection and
address allocation belong to higher-layer policy. Scanning records descriptors
without automatically polling their pending-address list. ``ScanDuration`` is
a 2024 symbol count, not the older exponent encoding.

``examples/wireless/ieee802154managed`` supplies a small native higher-layer
client. A device discovers a PAN, joins, sends DATA, sleeps, polls for a queued
reply, leaves and repeats with a new allocation. Run both typed/raw-byte
configurations and inspect the application's completion and MSDU scalars.

The native profile also supports periodic beacons, tracking and slotted CAP
access. An associated device tracking its PAN coordinator may request a GTS;
the coordinator advertises its decision in subsequent beacons. GTS DATA and
explicit GTS deallocation are not yet supported. With an external clock, this
profile requires a fixed rate within ±40 ppm, an initial offset aligned to the
scheduling grid, and a
scheduling quantum that divides the 16 µs symbol. The supported
``OscillatorBasedClock`` configuration uses ``clockGranularity = 0`` and an
unchanged oscillator. Enhanced frames/IEs,
cryptographic security, TSCH, DSME, ranging and modern UWB are separate future
profiles. The retained :ned:`Ieee802154Mac` and :ned:`Ieee802154NarrowbandMac`
continue to serve explicit legacy configurations.

`Ipv6DuplicateAddressHeader` represents DAR/DAC as an ND packet header. Base code 0 carries an eight-byte owner identifier. Extended code suffixes 1–4 carry 8/16/24/32 ownership-verifier bytes. The serializer writes the reserved Code Prefix as zero; the decoder ignores it. Base messages write a zero reserved transaction byte and ignore that byte on reception. The registered IPv6 address follows the verifier. Named ICMPv6 types 157/158 and generic decoding allow an ND owner to receive these messages without a dependency on LoWPAN.

Unknown ND options preserve their complete raw bodies. SLLAO/TLLAO length one retains the existing Ethernet-specific representation. Other lengths preserve bytes as generic options. A native EUI-64 option is sixteen bytes: type, length two, eight canonical address bytes and six padding bytes. Serialization rejects inconsistent raw lengths. Ordinary ND supports the Ethernet representation and drops the new registration types or unsupported address representations before its typed consumers. Its packet-drop signal records those outcomes.

`Ipv6NdRegistrationWire.test` passes independent request/reply vectors for base and every extended verifier size, forced reserialization, every body truncation, reserved receive fields, unsupported code suffixes, invalid field lengths and an extreme invalid model code. It also checks exact raw ARO/unknown-option/native SLLAO/TLLAO round trips and preservation of the existing typed Ethernet option.

`Ipv6NdUnsupportedRegistration.test` runs a complete ordinary `StandardHost`. Seven literal IPv6 packets with computed ICMPv6 checksums enter its IPv6 receive queue. DAR, DAC, RS, RA, NS, NA and Redirect must traverse ordinary IPv6 dispatch and reach ordinary ND. The last five contain unsupported native64 link-layer options. The test requires seven IPv6 receive observations and seven ND drops. It uses the loopback interface identity for deterministic local delivery; it does not claim physical Ethernet reception. `LowpanMixedNeighbourDiscovery.test` remains a regression control for ordinary DAD on a mixed-interface node.

The independent review identified the two generic consumer abort paths and the initial new-type naming issue; the current type name and safe receive handling address those findings. This evidence covers representation and safe dispatch. It establishes no host/router registration state, refresh, multihop duplicate-address exchange or context distribution. Those remain P10/P11 production responsibilities.

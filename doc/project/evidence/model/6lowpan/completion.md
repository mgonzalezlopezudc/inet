## P8 — Stateful contexts

Production owner: per-interface `LowpanLayer` and its bounded `LowpanContextTable`; codec: `LowpanIphcCodec`. Prefix lengths 0–128 are merged with inline/link-derived IID bits with context precedence. Source and destination IDs are independent; context 0 can omit CID. Prefix-based multicast uses a context prefix of at most 64 bits. Compression permission and decompression validity are distinct. Static XML configuration is optional and defaults empty.

Direct evidence: `LowpanStatefulContexts` unit vectors and the [native protocol fixture](../../../../../tests/protocol/6lowpan/stateful-contexts.md). The native fixture requires ten literal input frames, six exact IPv6 deliveries, two invalid-context drops, one replacement invalidation, two reassembly completions, five fragments and one real radio data transmission. It proves exact expiry rejection, stable first-fragment snapshots, FRAGN-first invalidation on prefix replacement, multicast reconstruction and receive-only source permission in emitted bytes.

The [P8 verification record](p8-verification.json) retains exact changed-source hashes, commands, exit statuses and log paths. All selected checks pass: 12 units, 62 modules and six protocol fixtures/twelve parameter runs, matching debug/release builds, feature-off build/five shared modules/three IEEE 802.15.4 fingerprint configurations, and core-without-UDP build/three units/one stateful protocol fixture. The complete parent protocol fixture cannot execute unchanged against the parent API, so no runtime failing-parent claim is made.

## P14 virtual fragment forwarding

Optional native route-over forwarding uses bounded per-ingress VRBs for administratively declared compatible peers. It freezes the actual IPv6 route/native next hop, decrements only the outer Hop Limit and allocates a shared-namespace outgoing tag. First matched native success gates later output; pending data retains ingress-anchored deadlines and ACK-relative spacing. General decoded NHC headers become an outer inline-next-header IPHC prefix plus raw subsequent headers, or uncompressed dispatch when configured. Repartition and final carry flushing preserve original datagram size and byte coordinates.

Ordinary reassembly remains authoritative for unlisted peers, control/unknown first fragments, IPv6 policy hooks and unsupported egress choices. Native registration source validity is queried through the actual IPv6/ND owner before admission and continuation. Listed orphan FRAGN drops, including control fragments arriving before a classifiable FRAG1. Local compatible data still passes normal IPv6/hook processing, with a fixed profile cutoff even when overlapping ranges renew ordinary reassembly. Completion/failure/shutdown release active ownership while preserving finite identity and tag protection; copied module/frame identities and local signal snapshots make synchronous cancellation safe. Module recreation loses that history, and local MAC success does not confirm destination reassembly.

The [main fixture](../../../../../tests/protocol/6lowpan/fragment-forwarding.md) supplies 52 cases through actual radios, two PANs and full IPv6 routes. It proves early forwarding and exact UDP delivery, both IID/Hop-Limit expansion, smaller adaptation output, general HBH/UDP reconstruction, deep-header preflight fallback, route/hook/source-policy compatibility, first-ACK failure, size/shape conflicts, concurrent tags, resource limits and fixed lifetime boundaries. Seven ND/control types retain ordinary expiry. Five independently authored [lifecycle cases](../../../../../tests/protocol/6lowpan/fragment-forwarding-lifecycle.md) cover paused egress STOP/CRASH, observer cancellation and borrowed-payload lifetime, plus an ingress remaining stopped beyond retained-history expiry. Allocator units own full tag-space exhaustion/reuse coverage.

The [record](p14-vrb-verification.json) explicitly composes a preserved full checkpoint with a verified three-file private-name/unused-field transformation. The checkpoint passes 22 debug protocol fixtures/204 simulations, eight release fixtures/130 simulations, nineteen debug units and fourteen module fixtures per mode (38 normal completions and one existing expected initialization diagnostic). A core build without UDP, seven units and two module controls pass; exact feature/NED state is restored. Five profile-rejection controls are separate. After cleanup, fresh matching debug/release builds and all 52 main plus five lifecycle cases pass in each mode; 140 observations per mode match the checkpoint. All 148 primary and 83 detailed cross-mode rows match. Assertions establish debug semantics; release establishes completion and printed observations.

Scoped architecture, naming and source-seal checks pass. The recovered C++ gate executes with zero compiler errors and a warning exit status; independent diagnostic triage is retained without claiming a clean gate. Two older constant names are scheduled for the separate final naming audit. Source review and publication findings are closed; no baseline changes are made. These results complete P14's selected profile, while the final whole-tree matrix remains separate.

# IEEE 802.15.4 conventional superframe and GTS profile

This record closes the source and service mapping for B-00. It selects unsecured legacy frames over the existing 2450-MHz O-QPSK packet-level PHY, page 0 channels 11–26, conventional beacon superframes and conventional GTSs. It does not claim that the planned implementation or any new test has run. Enhanced beacons, cryptography, TSCH, DSME, alternative access mechanisms and other PHYs are outside this profile. ## PIB and constants

Table 8-36 and Table 10-5 use `†` for upper-layer read-only and `*` for optional attributes; all other supported attributes are writable. Reset with SetDefaultPib false retains values; true restores defaults, and randomized sequence defaults remain owned by the MAC. The controller owns event state, not a second PIB. `START-SUPERFRAME` applies BO/SO/role/channel together after validation. Before B1-02, scheduled configuration is refused; no writable PIB value may silently turn on an incomplete scheduler.

`aBaseSuperframeDuration=960`, `aBaseSlotDuration=60`, `aNumSuperframeSlots=16`, `aMinCapLength=440`, and `aMaxLostBeacons=4` are symbols/slots/counts from Table 8-35. `aGtsDescPersistenceTime=4` is superframes from Table 10-121. For BO 0–8, inactivity expires at `2 × 2^(8−BO)` superframes; for BO 9–14 it expires at two. The PHY's ten-symbol SHR is 160 microseconds and its symbol period is 16 microseconds. Superframe origins and CAP backoff grid use the selected device clock; physical airtime/CCA/turnaround and PHY `startAt` use simulation time. Conversion applies only to current/future clock targets; fixed-rate ±40-ppm clocks are in scope and midattempt clock modifications are not.

Table8-36 (PDF152–156),8.4.3.1 (PDF152) and Table8-11 (PDF122) make BO/BLE writes real PIB writes; none of the inspected SET clauses specifies their live-schedule activation boundary. B1-02's temporary refusal while active must be closed in B1-04. The selected model policy confirms a valid local write immediately (also while PHY down), retains the current advertised epoch, and uses new non-15 BO/BLE on the next unconstructed beacon at the old scheduled boundary; that actual beacon anchors the new cadence. A constructed/on-air beacon stays immutable. BO15 retires pending periodic duties immediately and sets SO15; an inactive scheduler is not started by SET alone. Validate all coupled fields and known incoming order constraints before writing; pending START/realignment remains local BUSY. No pending SET store or additional timer is required.

B1-02 owns the first operational outgoing CAP/BLE receive duty, anchored by the actual transmitted beacon. Ordinary reception ends at the active-period boundary; BLE reception ends after the actual beacon plus its applicable IFS and configured BLE backoff periods. SO15 has no CAP. This duty does not depend on macRxOnWhenIdle. B2-03 integrates managed exchanges, RX-ENABLE and incoming tracking with the same duty owner rather than supplying a deferred basic BLE implementation.

BLE duration consumes the authoritative macUnitBackoffPeriod, not a literal20-symbol period after accepting another value. Table10-1 specifies its N-period receiver cutoff without a CAP-end clamp;10.2.2.1 allows rather than requires sleeping during inactivity. A configured receive duty may therefore continue past the geometric CAP end. It neither extends CAP geometry nor permits later contention traffic:10.2.2.2 and7.3.1.4 independently bound transactions and BLE frame starts. `outgoingCapActive` reports this receive duty, not CAP transmission availability. Keep mandatory beacon preparation priority even if the configured duty is longer.

Clause10.2.4's beacon priority covers internally generated ACKs as well as ordinary receive/transmit work. Known mandatory preparation cannot be skipped merely because ACK readiness is pending. Clause8.2.5.4 (PDF122) requires a payload SET producing a beacon larger than phyMaxPacketSize to fail INVALID_PARAMETER without changing the PIB; validation must not allocate a BSN. Table8-36 defines an octet set, with no fixed52-byte limit in this edition. If pending destinations later grow, choose up to seven unique eligible destinations in FIFO order within the remaining PSDU byte budget, stopping at the first destination that cannot fit so later short addresses cannot overtake an older extended address. Then group the selected set short-before-extended on wire (7.3.1.6). Unadvertised transactions and configured payload remain stored. This advertisement policy does not introduce B3's later descriptor-pressure maintenance.

Table10-3's SYNC input has channel information and TrackBeacon, while acquisition uses the configured macBeaconOrder. B1-03 therefore enables valid public BO writes on a controller-enabled device without an active outgoing schedule, before acquisition. Such a write does not initiate beaconing. Live outgoing writes retain B1-04's activation policy above.

## Native service mapping

Native admission remains separate from accepted IEEE completion: zero/nonmonotonic IDs are INVALID_REQUEST, an unavailable client/module is UNAVAILABLE, conflicting active work is BUSY, and a not-yet-enabled service is UNSUPPORTED_OPERATION. PHY-only unavailability refuses radio-dependent operations through `admitRadio()` while local PIB access and queued indirect admission remain available through their existing paths; it does not make the MAC itself stopped. A local refusal retains packet ownership and has no IEEE confirmation. An accepted semantic error gives one terminal confirmation; cancellation, RESET and STOPPED remain local abort results, not invented IEEE status codes. In stop/reset/PHY loss, detach affected work, cancel owner events and release packets before callbacks, with pending completions delivered before RESET confirmation.

## Acquisition and tracking contract

Table10-3 and10.2.6 (PDF188–189,195) give SYNC channel information and TrackBeacon, with no IEEE confirmation. The native completion means local installation after actual channel/readiness preparation and acquisition setup; it does not mean a beacon was received. Pending installation may be canceled or aborted by reset/stop/PHY loss. After installation its request ID is no longer pending, so cancel returns NOT_PENDING; a fresh SYNC replaces that installation. Compare the installation identity after callbacks before continuing its work.

A valid BO SET during installed incoming tracking writes the PIB immediately but does not retime that installation's acquisition search or received epoch. The next explicit SYNC snapshots the current BO for acquisition; ongoing tracking follows qualifying received geometry. BO15 SET does not implicitly cancel incoming tracking. This is the selected live-SET model policy, not a specified IEEE activation boundary, and requires no pending SET store/timer. A SYNC request with BO15 or broadcast PAN has an accepted native INVALID_PARAMETER configuration completion without installing search/tracking or changing an existing installation. IEEE supplies no SYNC.confirm; that result is local validation rather than an invented IEEE primitive/status mapping.

For valid replacement, local admission refusal or semantic rejection preserves the old installation. Once the validated replacement is accepted, retire the old events, anchors and miss accounting before new channel/readiness preparation. Preparation failure or cancellation then settles the new request exactly once and leaves no tracker; it does not resurrect old tracking or issue BEACON_LOST for explicit retirement. Actual PHY channel/state remains truthful, with no promised old-channel rollback. Fresh SYNC is required after such failure. This minimal native policy follows Table10-3's new-request semantics; the standard specifies no rollback guarantee and no second saved scheduler is needed.

Before B2-02, actual incoming/outgoing beacon state continues to gate contention DATA/commands even if an upper-layer BO15 write changes the PIB. The write must not accidentally re-enable unslotted traffic in an installed beacon PAN.

Start each initial acquisition search at actual receiver readiness and allow at most `960 × (2^BO + 1)` local symbols. Repeat failed searches until four consecutive failures. TrackBeacon=false stops after the next qualifying beacon, including when replacing an already tracked installation; it does not reduce failed acquisition to one search. TrackBeacon=true predicts subsequent windows from the latest qualifying actual beacon and valid geometry. Four consecutive failed tracking windows produce BEACON_LOST after detaching the old installation. Explicit SYNC is required to reacquire after loss.

The selected deadline policy accepts a valid beacon completing exactly at the window deadline and rejects a later completion for that expired window. Equal-time event ordering must implement that rule. A completion after an earlier acquisition deadline may qualify in the following repeated search; the final fourth deadline is the decisive boundary test. Keep full clock values for epochs/deadlines, using24-bit values only for service timestamps.

The numerical tracking guard is model policy: clocks are individually within±40ppm, and a conservative81ppm relative-rate bound covers their exact worst-case ratio. Grow uncertainty with elapsed time since the last successful anchor, including all missed intervals. Clause6.6.5/Figure6-7 (PDF74–75) motivate elapsed-time drift; they do not prescribe this numerical window or its propagation allowance.

The selected external clock has fixed configuration and a nominal/scheduling quantum dividing the16-microsecond O-QPSK symbol, with its initial offset on that grid. For the current OscillatorBasedClock this means clockGranularity=0, using its nominal oscillator tick; the tested default tick is1 microsecond. This is a profile precondition, not a runtime-verified universal IClock guarantee. IClock exposes no granularity query. With no external clock,16 microseconds must be representable at the simulation resolution. Arbitrary clock steps, rate changes and incompatible grids remain outside scope.

Use integer arithmetic to round allowances outward to whole symbols, starting from the already representable sampled local anchor. Let S=16 microseconds, rho=81/1,000,000 and elapsedBI be the full local-clock interval since the last qualifying anchor:

```text
E = copiedLocalAnchor + elapsedBI
U = ceilToS(rho * elapsedBI
            + (1 + rho) * (2*S + maxPropagationDelay + 2 simulation ticks))
wake = E - U - ceilToS((1 + rho) * actualPhyTurnaround)
deadline = E + U + ceilToS((1 + rho) * maximumPhysicalBeaconPPDU)
```

The scaled two-symbol allowance covers both anchor quantizations, propagation variation and simulation rounding. The default192-microsecond turnaround becomes208 microseconds; allow the complete maximum127-byte beacon PPDU. All resulting targets remain on-grid, so up/down/closer/none scheduling modes cannot move them inward. Capture the deadline's physical inverse while it is future and compare actual completion with that value; a floored clock sample cannot distinguish the deadline from one simulation tick later. Process an already-due wake immediately and an expired window through its expiry path without inverse-converting a historical target. Equal-time valid packet processing precedes expiry.

An installed tracker retains logical phase and miss accounting during PHY-only outage; pending installation instead aborts STOPPED. Recovery before four misses resumes applicable duties, while recovery after loss cannot resurrect retired tracking. Reset/MAC stop/crash retire all installation state, events and anchors before callbacks.

Notification and synchronization admission are separate predicates. The pinned2024 text in10.2.6/PDF189 literally calls a beacon whose source/PAN does not match the configured coordinator/PAN a “tracking Beacon” for notification. Preserve that notification condition alongside8.2.4.3's !macAutoRequest, nonempty payload and macNotifyAllBeacons conditions; do not silently replace the edition's wording with “match.” Renewal of parent timing still requires the configured coordinator/PAN, valid supported geometry, actual receive-start anchor and supported security. A foreign notification must never reset its loss counter. This interpretation retains the table's synchronization-with-coordinator semantics without treating notification as synchronization.

## Slotted PHY readiness and grid alignment

For B2-02,6.3.2.1 and10.11/Figure10-127 (PDF63–64,319–321) require the beacon-aligned grid, two clear CCAs and boundary-aligned transmission. They do not specify the immediately next boundary after CCA2. Clause11.2.3's turnaround bound (PDF595) begins at a received PPDU's trailing edge, not CCA completion. The native PHY has one operation slot, so CCA and TX readiness remain sequential.

The selected packet-model policy chooses the first backoff boundary whose converted simulation time is at or after actual PHY readiness. Compute the candidate from CCA2 completion plus published turnaround while future, including that opportunity in CAP/BLE fit checks. After readiness confirmation, transmit only if it is still current/future and the window remains valid; otherwise advance through the appropriate fit/defer path. This extra grid wait adds no random draw, CCA, NB/BE change or CW reset.

With a+40ppm clock, a local320-microsecond period lasts about319.9872005 physical microseconds. Physical128-microsecond CCA plus192-microsecond preparation misses that next boundary by about12.8 nanoseconds, so the following boundary is selected. Zero/negative drift can use the immediately following boundary. This is an abstraction consequence, not an IEEE-mandated extra period. Do not scale PHY durations or overlap operations to hide it. A floored clock sample can still name a physically passed boundary; compare the converted candidate against readiness, not only a ceiling of current clock time. Direct checks must include that plateau, unchanged RNG/backoff state and a frame fitting only the earlier nominal CAP/BLE opportunity.

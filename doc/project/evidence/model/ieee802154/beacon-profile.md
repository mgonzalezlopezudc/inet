## Native service mapping

Native admission remains separate from accepted IEEE completion: zero/nonmonotonic IDs are INVALID_REQUEST, an unavailable client/module is UNAVAILABLE, conflicting active work is BUSY, and a not-yet-enabled service is UNSUPPORTED_OPERATION. PHY-only unavailability refuses radio-dependent operations through `admitRadio()` while local PIB access and queued indirect admission remain available through their existing paths; it does not make the MAC itself stopped. A local refusal retains packet ownership and has no IEEE confirmation. An accepted semantic error gives one terminal confirmation; cancellation, RESET and STOPPED remain local abort results, not invented IEEE status codes. In stop/reset/PHY loss, detach affected work, cancel owner events and release packets before callbacks, with pending completions delivered before RESET confirmation.

## Acquisition and tracking contract

Table10-3 and10.2.6 (PDF188–189,195) give SYNC channel information and TrackBeacon, with no IEEE confirmation. The native completion means local installation after actual channel/readiness preparation and acquisition setup; it does not mean a beacon was received. Pending installation may be canceled or aborted by reset/stop/PHY loss. After installation its request ID is no longer pending, so cancel returns NOT_PENDING; a fresh SYNC replaces that installation. Compare the installation identity after callbacks before continuing its work.

A valid BO SET during installed incoming tracking writes the PIB immediately but does not retime that installation's acquisition search or received epoch. The next explicit SYNC snapshots the current BO for acquisition; ongoing tracking follows qualifying received geometry. BO15 SET does not implicitly cancel incoming tracking. This is the selected live-SET model policy, not a specified IEEE activation boundary, and requires no pending SET store/timer. A SYNC request with BO15 or broadcast PAN has an accepted native INVALID_PARAMETER configuration completion without installing search/tracking or changing an existing installation. IEEE supplies no SYNC.confirm; that result is local validation rather than an invented IEEE primitive/status mapping.

For valid replacement, local admission refusal or semantic rejection preserves the old installation. Once the validated replacement is accepted, retire the old events, anchors and miss accounting before new channel/readiness preparation. Preparation failure or cancellation then settles the new request exactly once and leaves no tracker; it does not resurrect old tracking or issue BEACON_LOST for explicit retirement. Actual PHY channel/state remains truthful, with no promised old-channel rollback. Fresh SYNC is required after such failure. This minimal native policy follows Table10-3's new-request semantics; the standard specifies no rollback guarantee and no second saved scheduler is needed.

Before B2-02, actual incoming/outgoing beacon state continues to gate contention DATA/commands even if an upper-layer BO15 write changes the PIB. The write must not accidentally re-enable unslotted traffic in an installed beacon PAN.

Start each initial acquisition search at actual receiver readiness and allow at most `960 × (2^BO + 1)` local symbols. Repeat failed searches until four consecutive failures. TrackBeacon=false stops after the next qualifying beacon, including when replacing an already tracked installation; it does not reduce failed acquisition to one search. TrackBeacon=true predicts subsequent windows from the latest qualifying actual beacon and valid geometry. Four consecutive failed tracking windows produce BEACON_LOST after detaching the old installation. Explicit SYNC is required to reacquire after loss.

The selected deadline policy accepts a valid beacon completing exactly at the window deadline and rejects a later completion for that expired window. Equal-time event ordering must implement that rule. A completion after an earlier acquisition deadline may qualify in the following repeated search; the final fourth deadline is the decisive boundary test. Keep full clock values for epochs/deadlines, using24-bit values only for service timestamps.

The numerical tracking guard is model policy: clocks are individually within±40ppm, and a conservative81ppm relative-rate bound covers their exact worst-case ratio. Grow uncertainty with elapsed time since the last successful anchor, including all missed intervals. Clause6.6.5/Figure6-7 (PDF74–75) motivate elapsed-time drift; they do not prescribe this numerical window or its propagation allowance.

The selected external clock has fixed configuration and a nominal/scheduling quantum dividing the16-microsecond O-QPSK symbol, with its initial offset on that grid. For the current OscillatorBasedClock this means clockGranularity=0, using its nominal oscillator tick; the tested default tick is1 microsecond. This is a profile precondition, not a runtime-verified universal IClock guarantee. IClock exposes no granularity query. With no external clock,16 microseconds must be representable at the simulation resolution. Arbitrary clock steps, rate changes and incompatible grids remain outside scope.

Use integer arithmetic to round allowances outward to whole symbols, starting from the already representable sampled local anchor. Let S=16 microseconds, rho=81/1,000,000 and elapsedBI be the full local-clock interval since the last qualifying anchor:

```text
E = copiedLocalAnchor + elapsedBI
U = ceilToS(rho * elapsedBI
            + (1 + rho) * (2*S + maxPropagationDelay + 2 simulation ticks))
wake = E - U - ceilToS((1 + rho) * actualPhyTurnaround)
deadline = E + U + ceilToS((1 + rho) * maximumPhysicalBeaconPPDU)
```

The scaled two-symbol allowance covers both anchor quantizations, propagation variation and simulation rounding. The default192-microsecond turnaround becomes208 microseconds; allow the complete maximum127-byte beacon PPDU. All resulting targets remain on-grid, so up/down/closer/none scheduling modes cannot move them inward. Capture the deadline's physical inverse while it is future and compare actual completion with that value; a floored clock sample cannot distinguish the deadline from one simulation tick later. Process an already-due wake immediately and an expired window through its expiry path without inverse-converting a historical target. Equal-time valid packet processing precedes expiry.

An installed tracker retains logical phase and miss accounting during PHY-only outage; pending installation instead aborts STOPPED. Recovery before four misses resumes applicable duties, while recovery after loss cannot resurrect retired tracking. Reset/MAC stop/crash retire all installation state, events and anchors before callbacks.

Notification and synchronization admission are separate predicates. The pinned2024 text in10.2.6/PDF189 literally calls a beacon whose source/PAN does not match the configured coordinator/PAN a “tracking Beacon” for notification. Preserve that notification condition alongside8.2.4.3's !macAutoRequest, nonempty payload and macNotifyAllBeacons conditions; do not silently replace the edition's wording with “match.” Renewal of parent timing still requires the configured coordinator/PAN, valid supported geometry, actual receive-start anchor and supported security. A foreign notification must never reset its loss counter. This interpretation retains the table's synchronization-with-coordinator semantics without treating notification as synchronization.

## Coordinator role and parent association

Normal received Coordinator Realignment preserves M2's upper-directed contract:10.2.5/PDF188 delivers REALIGNMENT with the command's parameters, and the upper layer follows up through START-SUPERFRAME/SET as appropriate. Receipt alone does not commit a new channel/PAN or synthesize tracking geometry. The selected model retains the existing installation/configuration until explicit replacement, normal loss or lifecycle retirement. The legacy7.5.4/Figure7-30 body carries PAN/coordinator-short/channel/device-short information, not BO/SO/StartTime. A new incoming-order/overlap decision therefore requires actual subsequent configuration/beacon evidence; a same-channel qualifying beacon can supply it without an upper retune. Compare before rearming outgoing transmission, retiring it with SUPERFRAME_OVERLAP when required. Orphan scanning retains its distinct existing automatic recovery/retune owner. No pending received-realignment cache is added.

A generic coordinator serves children independently of whether it transmits periodic beacons. Keep that private role distinct from the PAN-principal role used for the beacon PAN Coordinator bit and PAN-conflict authority (3.1/PDF43,7.3.1.4/PDF88,10.2.2.5/PDF184–185). Successful existing START or START-SUPERFRAME commits the role; a failed request preserves it. BO15, PHY outage, nondefault reset and the existing stop/restart retain it; default reset restores the configured initial role. An associated child can use START-SUPERFRAME(false,BO15) to become a coordinator before serving its own child's BO15 association, then enable linked periodic schedules. No new public role service or configuration is required.

Indirect DATA, association, polling, downstream disassociation and orphan response require generic coordinator authority and their existing membership checks. PAN-conflict principal handling and the beacon PAN bit remain PAN-coordinator-only. Association/orphan-scan exclusions remain limited to the PAN coordinator. Promoting a child or retiring its outgoing schedule does not erase its parent binding or same-PAN downstream membership.

Clause10.2.4 requires a child to have successfully associated before starting beacons. Table10-2/PDF194 supplies no dedicated unassociated result. The selected native validation mapping for an unassociated child START is accepted INVALID_PARAMETER using8.2.2's generic validation vocabulary; this mapping is not an additional quoted IEEE status. Keep the existing NO_SHORT_ADDRESS and nonzero TRACKING_OFF cases distinct.

An existing M2 distinction is scheduled for B2-03: Table10-111/PDF374 defines macAssociatedPanCoord specifically as association through the PAN coordinator, but the baseline uses it as generic parent-association presence. B2-03 must separate actual parent binding from that principal metadata before closing managed three-node operation. The generic coordinator role must not absorb either association meaning; B1-04's BO15 setup does not claim that existing PIB distinction is already corrected.

The association boundary currently drops available parent-role context. Table8-3/PDF115–116 includes the received superframe/PAN bit in the discovery descriptor, but Table10-104/PDF365–367 has no corresponding association parameter; Association Response itself carries only short address/status (10.21.5.2/PDF363). The selected B2-03 mapping appends native `coordinatorIsPanCoordinator=true` to the association request. This is copied context, not a new IEEE primitive parameter. Discovery populates it from the successfully decoded selected descriptor; beacon-mode acquisition can use the actual matching beacon. The legacy configured default preserves the existing caller declaration that its target is the PAN coordinator; configured child-parent calls explicitly pass false. It is caller-supplied knowledge, not over-the-air verification.

Commit established parent binding and principal metadata only on association success. Generic parent matching, leave, realignment authority and broadcast reception consume the binding, while principal-specific conflict logic consumes macAssociatedPanCoord. Tentative PIB/channel/address preparation does not establish association. Orphan recovery preserves the established parent's principal metadata because its Realignment command supplies no PAN bit. This requires no beacon cache or cross-request correlation.

## Slotted PHY readiness and grid alignment

For B2-02,6.3.2.1 and10.11/Figure10-127 (PDF63–64,319–321) require the beacon-aligned grid, two clear CCAs and boundary-aligned transmission. They do not specify the immediately next boundary after CCA2. Clause11.2.3's turnaround bound (PDF595) begins at a received PPDU's trailing edge, not CCA completion. The native PHY has one operation slot, so CCA and TX readiness remain sequential.

The selected packet-model policy chooses the first backoff boundary whose converted simulation time is at or after actual PHY readiness. Compute the candidate from CCA2 completion plus published turnaround while future, including that opportunity in CAP/BLE fit checks. After readiness confirmation, transmit only if it is still current/future and the window remains valid; otherwise advance through the appropriate fit/defer path. This extra grid wait adds no random draw, CCA, NB/BE change or CW reset.

With a+40ppm clock, a local320-microsecond period lasts about319.9872005 physical microseconds. Physical128-microsecond CCA plus192-microsecond preparation misses that next boundary by about12.8 nanoseconds, so the following boundary is selected. Zero/negative drift can use the immediately following boundary. This is an abstraction consequence, not an IEEE-mandated extra period. Do not scale PHY durations or overlap operations to hide it. A floored clock sample can still name a physically passed boundary; compare the converted candidate against readiness, not only a ceiling of current clock time. Direct checks must include that plateau, unchanged RNG/backoff state and a frame fitting only the earlier nominal CAP/BLE opportunity.

### Search, fallback and retry ownership

Clause10.2.7 (physical PDF190, printed189) gives a nontracking transmitter one search of960*(2^BO+1) symbols, starting at actual RX readiness. A never-transmitted queued DATA retains its packet/DSN through continuous-tracking misses1–3; actual loss retires the old access grant without completing DATA, then permits that transaction-owned search and eventual unslotted fallback only after the complete unsuccessful search. A found beacon supplies its actual CAP without requiring continuous SYNC installation. No NO_BEACON DATA confirmation or duplicate SYNC-loss indication is invented. Under6.6.3.4/PDF73, an already on-air CAP frame's retry remains restricted to CAP even while reacquiring; do not generalize unsent fallback to that retry. If its search fails, that pending retry remains eligible to consume a later matching parent beacon and resume in the supplied CAP, without implicitly reinstalling continuous tracking. Cancellation/reset/PHY-unavailability retain their existing terminals.

### Slotted ACK wait

Clause6.6.3.3/PDF72–73 permits CAP ACK start at AIFS or a backoff boundary between AIFS and AIFS+macUnitBackoffPeriod, inclusive. Participants must share the selected PAN backoff-period value; an arbitrary unknown peer period is outside this bounded profile. The selected PHY has AIFS192 microseconds and legacy ACK PPDU352 microseconds. For Q=AIFS+nominalBackoffPeriod and rho=81/1,000,000, use the following physical bound for both ACK reception deadline and acknowledged-exchange CAP fit:

```text
slottedAckWait = ackPpduDuration + Q + ceilToSimulationTick(rho*Q)
                 + 2*maxPropagationDelay + 2 simulation ticks
```

The default is864.041472 microseconds plus round-trip propagation and rounding allowance. The bound uses existing local parameters and the declared clock-rate envelope, with no peer-clock inspection or new propagation parameter. Preserve the existing unslotted544-microsecond base. Test a legal later-boundary ACK at both drift extremes, timeout equality/one-tick overflow, and a transaction fitting the old544-microsecond allowance but not the corrected full CAP budget. Whole-symbol rounding is unnecessary for this physical timer; representable grid targets already prevent extra scheduling-grid rounding.

### Local CCA postponement and whole-CAP budget

An unperformed CCA postponed by local IFS/ACK arbitration is neither clear nor busy. The selected deferCca scheduling handback preserves NB/BE/CW and draws no random delay, then resumes on the first eligible grid boundary after both physical eligibility and actual RX readiness. Recheck CAP/BLE fit. Detach the MAC's held-CCA obligation before notifying the provider because a current-boundary response can reenter synchronously. While ACK completion is unknown, retain the obligation; an ordinary MAC timer must never perform a slotted CCA directly at an off-grid eligibility time. Figure10-127 prescribes CW changes for actual assessments, not this local scheduling handback.

Copy actual physical beacon end and the future-converted CAP end when observing an epoch. Ordinary CAP begins at beacon end (10.2.2.2/PDF184); do not subtract a received beacon's IFS universally. Section6.3.1/PDF62 imposes IFS between frames transmitted from one device; BLE's explicit beacon-IFS countdown rule and the sender's own prior-transmission eligibility remain separate.

Under8.3.5/Table8-31 continuation and definition3.1/PDF44, DATA plus required ACK allowance plus final IFS exceeding that copied full physical CAP budget is a sufficient FRAME_TOO_LONG proof. Equality passes the size test. CSMA-CA steps are separate: remaining-window feasibility also includes CCA, readiness, grid and eligibility, and failure there defers rather than becoming a false size error. This size test does not claim complete proof of every permanently unusable access geometry. A stronger zero-backoff opportunity check belongs to the provider's existing calculation in a fresh window, not duplicated in the epoch owner or implemented through historical clock conversion.

### Child-coordinator start offset

Clause10.2.4 (PDF187–188, `ieee802154-2024:clause:10.2.4`) requires nonzero child StartTime to be rounded to a backoff-period boundary but does not specify a direction. The selected model rounds the requested symbol offset upward to the first boundary at or after that offset, measured from the received parent beacon anchor. An already aligned offset is unchanged; zero retains its explicit immediate-start meaning. This policy avoids starting before the requested offset and is tested at a boundary and one symbol on either side. It is an implementation choice, not an additional quoted IEEE rounding rule.

Table10-1 (PDF192–194) permits the full24-bit StartTime range without a separate less-than-BI restriction. Keep the rounded value in a wide integer and test periodic overlap modulo the common beacon interval; do not reject a valid value solely because it exceeds one BI. If the computed nonzero target or its necessary preparation has already passed, the model advances by whole BIs to the first usable future occurrence of that phase. It does not transmit immediately off phase or catch up missed beacons. This late-request policy is also an explicit model choice; zero still means immediate actual PHY preparation.

The full rounded offset determines the first target once, relative to the accepted request's anchor; later parent renewals must not repeatedly restart a multi-BI initial delay. After the first actual start, retain only the recurring phase modulo BI. For a zero-start child with installed tracking, derive that phase from its actual first beacon; it remains linked for reanchoring and four-miss shutdown. Zero without tracking keeps its explicit immediate behavior. A nonzero child request with no installed tracker gives TRACKING_OFF. If a tracker exists on a different channel, the selected native mapping rejects the unsupported phase/channel combination with INVALID_PARAMETER before retuning; this is model validation via8.2.2, not a new quoted IEEE status condition. PAN-coordinator, BO15 and zero-offset ignored-StartTime cases remain exempt.

Replacing an active child schedule keeps its committed periodic target separate from the pending request's first target. Select the earlier through the existing single preparation event, retaining old cadence and old frame configuration until the new first transmission commits. Failure or cancellation preserves the old cadence. Parent renewal may reanchor that committed cadence without overwriting the pending first target. ACK/access reservations use the same earliest target; no general timer broker or second schedule owner is introduced.

SO15 has no active portion after the beacon; it does not make the beacon's occupied airtime zero. Clause10.2.2.1/PDF183 limits the ordinary SD formula to SO≤BO≤14, and10.2.2.5/PDF184 separately forbids overlapping parent/child beacons. Linked overlap checks therefore use full SD for ordinary SO and actual beacon PPDU extents for SO15, across the common BI's wrap boundary. Copy the received extent at observation and use the actual constructed outgoing candidate's encoded length. Keep no-CAP semantics and treat PHY preparation separately; neither a fictitious zero-length beacon nor an invented SD/CAP is valid.

Table10-2/PDF194 does not exempt StartTime zero from SUPERFRAME_OVERLAP; its nonzero condition applies only to TRACKING_OFF. Zero requests remain immediate and need no tracker when incoming geometry is unknown. With known incoming geometry, check the actual prepared first candidate before transmission, including previously nonbeaconing realignment. An immediate timing request cannot authorize known overlap. Retain a clear-phase zero-start loss control separately from the negative known-overlap case.

SO15's occupied intervals use exact physical simtime_t, with overlap iff childStart<parentEnd and parentStart<childEnd. Use actual copied received PPDU edges and future-converted child/expected-parent starts. Capture needed surrounding parent phase edges while future, retaining the previous edge as existing tracking/schedule work advances; do not reconstruct a historical edge by subtracting a future-cycle physical BI, because quantized inversion can differ by one tick. Predicted parent occurrences reuse the last observed physical PPDU duration as an explicit known-length assumption, refreshed on reception. Future conversions are decision-time snapshots, not immutable forecasts: the internal clock backend can adjust their numerical result as its origin advances. Existing tracking guards and actual PHY turnaround remain separate. Exact one-tick/equality geometry is checked with simulation time or zero drift; external-clock tests compare independently derived local targets converted at the actual submission decision rather than nominal local deltas or stale physical predictions.

Under10.2.4/PDF188, scheduled beacon transmission has priority over other RX operations. The native PHY can abandon reception when preparing TRANSMIT, then performs its real turnaround. Do not postpone a beacon merely because a PPDU extends past preparation but ends before its TX target. An abandoned parent reception counts as unsuccessful tracking reception. Actual known beacon-airtime overlap remains subject to the geometry checks above; preparation is not extra on-air extent. Test waveform ends one tick before, equal to and after preparation with on-target beacon TX in all three cases, and observe local abandonment separately from the continuing propagated waveform. No early frame-identity peek or new PHY API is needed.

For a forecast parent occurrence under an external clock, reserve uncertainty separately from that exact physical geometry. Use the existing declared fixed-rate envelope and elapsed time since the last actual anchor, including anchor quantization; no peer-clock inspection is permitted. In physical simulation ticks, let base=two symbols+maxPropagationDelay+two ticks and reserve ceil(81ppm×elapsed)+base+ceil(81ppm×base) on each forecast edge. The existing clock owner supplies this bound, or zero for its simulation-time fallback. No whole-symbol rounding is needed for this physical comparison. A constant known PPDU length alone cannot guarantee separation under opposite drift. The physical interval helper remains exact, and actual observed edges do not acquire a fictitious longer PPDU. This reservation is a conservative model policy, distinct from the receive tracking guard and PHY preparation. The B1-04 regression must include the near-boundary BO3/SO15 case with parent+40ppm, child−40ppm, StartTime7640 symbols and a640-microsecond child PPDU, where an unguarded forecast passes while actual transmissions overlap.

### Access-grant retirement and equal-time preparation

A linked coordinator's incoming and outgoing CAPs are different direct-link opportunities (10.2.2.5/PDF184–185,10.2.7/PDF190). Mark each copied window's origin and choose the transaction's side centrally from the established parent, downstream context and existing procedure/broadcast ownership. Filter the single current-window cache before both initial access and deferred update: a wrong-side beacon cannot authorize transmission or unslotted fallback. Retain packet, DSN and accepted provider state until the applicable CAP arrives. Nonoverlapping linked schedules require no window registry, second provider or per-command router; realignment broadcasts use the outgoing side.

A CAP grant belongs to its received or transmitted beacon epoch. An accepted replacement SYNC retires the prior grant before any new installation callback can submit traffic, including when channel SET and RX readiness complete inline. A provider refusal before accepting replacement preserves the old installed tracker and grant. No grant may cross a channel replacement merely because its old physical end is still future.

Retiring only outgoing timing on the same channel preserves any current incoming grant/tracker. On successful START/realignment configuration activation to a different channel, retire the obsolete incoming geometry/grant and an installation bound to the old channel; its earlier installation completion creates no new SYNC confirmation or invented IEEE loss reason. Acquiring the new channel requires explicit SYNC. Continuing associated child operation retains a tracker already naming the committed channel. Becoming the PAN coordinator starts a new PAN and retires old parent tracking, geometry, linked phase and references at successful commit even on the same channel; preserve the device's own short identity, and clear downstream membership when the PAN changes. The PIB owner clears its parent references directly rather than ignoring a rejected upper-style SET of an unset value. This is a selected local replacement policy consistent with existing START semantics. Do not retire committed incoming context merely on preparatory PHY SET success: failure/rollback before configuration commit must preserve it.

Coordinator beacon preparation follows equal-time packet delivery and ACK-timeout completion. The inclusive radio-completion reservation therefore permits an ACK or its deadline exactly at preparation without skipping the mandatory beacon. This ordering must hold for simulation time and both supported OscillatorBasedClock event backends, with cancellation/reset retiring any pending preparation dispatch. Final IFS may overlap radio preparation; advertised CAP geometry remains unchanged.

## Native service mapping

Native admission remains separate from accepted IEEE completion: zero/nonmonotonic IDs are INVALID_REQUEST, an unavailable client/module is UNAVAILABLE, conflicting active work is BUSY, and a not-yet-enabled service is UNSUPPORTED_OPERATION. PHY-only unavailability refuses radio-dependent operations through `admitRadio()` while local PIB access and queued indirect admission remain available through their existing paths; it does not make the MAC itself stopped. A local refusal retains packet ownership and has no IEEE confirmation. An accepted semantic error gives one terminal confirmation; cancellation, RESET and STOPPED remain local abort results, not invented IEEE status codes. In stop/reset/PHY loss, detach affected work, cancel owner events and release packets before callbacks, with pending completions delivered before RESET confirmation.

## Acquisition and tracking contract

Table10-3 and10.2.6 (PDF188–189,195) give SYNC channel information and TrackBeacon, with no IEEE confirmation. The native completion means local installation after actual channel/readiness preparation and acquisition setup; it does not mean a beacon was received. Pending installation may be canceled or aborted by reset/stop/PHY loss. After installation its request ID is no longer pending, so cancel returns NOT_PENDING; a fresh SYNC replaces that installation. Compare the installation identity after callbacks before continuing its work.

A valid BO SET during installed incoming tracking writes the PIB immediately but does not retime that installation's acquisition search or received epoch. The next explicit SYNC snapshots the current BO for acquisition; ongoing tracking follows qualifying received geometry. BO15 SET does not implicitly cancel incoming tracking. This is the selected live-SET model policy, not a specified IEEE activation boundary, and requires no pending SET store/timer. A SYNC request with BO15 or broadcast PAN has an accepted native INVALID_PARAMETER configuration completion without installing search/tracking or changing an existing installation. IEEE supplies no SYNC.confirm; that result is local validation rather than an invented IEEE primitive/status mapping.

For valid replacement, local admission refusal or semantic rejection preserves the old installation. Once the validated replacement is accepted, retire the old events, anchors and miss accounting before new channel/readiness preparation. Preparation failure or cancellation then settles the new request exactly once and leaves no tracker; it does not resurrect old tracking or issue BEACON_LOST for explicit retirement. Actual PHY channel/state remains truthful, with no promised old-channel rollback. Fresh SYNC is required after such failure. This minimal native policy follows Table10-3's new-request semantics; the standard specifies no rollback guarantee and no second saved scheduler is needed.

Before B2-02, actual incoming/outgoing beacon state continues to gate contention DATA/commands even if an upper-layer BO15 write changes the PIB. The write must not accidentally re-enable unslotted traffic in an installed beacon PAN.

Start each initial acquisition search at actual receiver readiness and allow at most `960 × (2^BO + 1)` local symbols. Repeat failed searches until four consecutive failures. TrackBeacon=false stops after the next qualifying beacon, including when replacing an already tracked installation; it does not reduce failed acquisition to one search. TrackBeacon=true predicts subsequent windows from the latest qualifying actual beacon and valid geometry. Four consecutive failed tracking windows produce BEACON_LOST after detaching the old installation. Explicit SYNC is required to reacquire after loss.

The selected deadline policy accepts a valid beacon completing exactly at the window deadline and rejects a later completion for that expired window. Equal-time event ordering must implement that rule. A completion after an earlier acquisition deadline may qualify in the following repeated search; the final fourth deadline is the decisive boundary test. Keep full clock values for epochs/deadlines, using24-bit values only for service timestamps.

The numerical tracking guard is model policy: clocks are individually within±40ppm, and a conservative81ppm relative-rate bound covers their exact worst-case ratio. Grow uncertainty with elapsed time since the last successful anchor, including all missed intervals. Clause6.6.5/Figure6-7 (PDF74–75) motivate elapsed-time drift; they do not prescribe this numerical window or its propagation allowance.

The selected external clock has fixed configuration and a nominal/scheduling quantum dividing the16-microsecond O-QPSK symbol, with its initial offset on that grid. For the current OscillatorBasedClock this means clockGranularity=0, using its nominal oscillator tick; the tested default tick is1 microsecond. This is a profile precondition, not a runtime-verified universal IClock guarantee. IClock exposes no granularity query. With no external clock,16 microseconds must be representable at the simulation resolution. Arbitrary clock steps, rate changes and incompatible grids remain outside scope.

Use integer arithmetic to round allowances outward to whole symbols, starting from the already representable sampled local anchor. Let S=16 microseconds, rho=81/1,000,000 and elapsedBI be the full local-clock interval since the last qualifying anchor:

```text
E = copiedLocalAnchor + elapsedBI
U = ceilToS(rho * elapsedBI
            + (1 + rho) * (2*S + maxPropagationDelay + 2 simulation ticks))
wake = E - U - ceilToS((1 + rho) * actualPhyTurnaround)
deadline = E + U + ceilToS((1 + rho) * maximumPhysicalBeaconPPDU)
```

The scaled two-symbol allowance covers both anchor quantizations, propagation variation and simulation rounding. The default192-microsecond turnaround becomes208 microseconds; allow the complete maximum127-byte beacon PPDU. All resulting targets remain on-grid, so up/down/closer/none scheduling modes cannot move them inward. Capture the deadline's physical inverse while it is future and compare actual completion with that value; a floored clock sample cannot distinguish the deadline from one simulation tick later. Process an already-due wake immediately and an expired window through its expiry path without inverse-converting a historical target. Equal-time valid packet processing precedes expiry.

An installed tracker retains logical phase and miss accounting during PHY-only outage; pending installation instead aborts STOPPED. Recovery before four misses resumes applicable duties, while recovery after loss cannot resurrect retired tracking. Reset/MAC stop/crash retire all installation state, events and anchors before callbacks.

Notification and synchronization admission are separate predicates. The pinned2024 text in10.2.6/PDF189 literally calls a beacon whose source/PAN does not match the configured coordinator/PAN a “tracking Beacon” for notification. Preserve that notification condition alongside8.2.4.3's !macAutoRequest, nonempty payload and macNotifyAllBeacons conditions; do not silently replace the edition's wording with “match.” Renewal of parent timing still requires the configured coordinator/PAN, valid supported geometry, actual receive-start anchor and supported security. A foreign notification must never reset its loss counter. This interpretation retains the table's synchronization-with-coordinator semantics without treating notification as synchronization.

## Coordinator role and parent association

Normal received Coordinator Realignment preserves M2's upper-directed contract:10.2.5/PDF188 delivers REALIGNMENT with the command's parameters, and the upper layer follows up through START-SUPERFRAME/SET as appropriate. Receipt alone does not commit a new channel/PAN or synthesize tracking geometry. The selected model retains the existing installation/configuration until explicit replacement, normal loss or lifecycle retirement. The legacy7.5.4/Figure7-30 body carries PAN/coordinator-short/channel/device-short information, not BO/SO/StartTime. A new incoming-order/overlap decision therefore requires actual subsequent configuration/beacon evidence; a same-channel qualifying beacon can supply it without an upper retune. Compare before rearming outgoing transmission, retiring it with SUPERFRAME_OVERLAP when required. Orphan scanning retains its distinct existing automatic recovery/retune owner. No pending received-realignment cache is added.

A generic coordinator serves children independently of whether it transmits periodic beacons. Keep that private role distinct from the PAN-principal role used for the beacon PAN Coordinator bit and PAN-conflict authority (3.1/PDF43,7.3.1.4/PDF88,10.2.2.5/PDF184–185). Successful existing START or START-SUPERFRAME commits the role; a failed request preserves it. BO15, PHY outage, nondefault reset and the existing stop/restart retain it; default reset restores the configured initial role. An associated child can use START-SUPERFRAME(false,BO15) to become a coordinator before serving its own child's BO15 association, then enable linked periodic schedules. No new public role service or configuration is required.

Indirect DATA, association, polling, downstream disassociation and orphan response require generic coordinator authority and their existing membership checks. PAN-conflict principal handling and the beacon PAN bit remain PAN-coordinator-only. Association/orphan-scan exclusions remain limited to the PAN coordinator. Promoting a child or retiring its outgoing schedule does not erase its parent binding or same-PAN downstream membership.

Clause10.2.4 requires a child to have successfully associated before starting beacons. Table10-2/PDF194 supplies no dedicated unassociated result. The selected native validation mapping for an unassociated child START is accepted INVALID_PARAMETER using8.2.2's generic validation vocabulary; this mapping is not an additional quoted IEEE status. Keep the existing NO_SHORT_ADDRESS and nonzero TRACKING_OFF cases distinct.

Table10-111/PDF374 defines macAssociatedPanCoord specifically as association through the PAN coordinator. The native model keeps established parent binding separate from that principal metadata. Generic coordinator authority remains a third, independent role: serving children does not establish a parent binding or imply association through the PAN coordinator.

Table8-3/PDF115–116 includes the received superframe/PAN bit in the discovery descriptor, but Table10-104/PDF365–367 has no corresponding association parameter; Association Response itself carries only short address/status (10.21.5.2/PDF363). The native association request appends `coordinatorIsPanCoordinator=true` as copied context. Discovery populates it from the successfully decoded selected descriptor, and an actual matching acquired beacon supplies authoritative role context for beacon operation. The configured default preserves the caller declaration that its target is the PAN coordinator; configured child-parent calls explicitly pass false. The added native field is not an IEEE primitive parameter or an independent verification of a configured peer.

Commit established parent binding and principal metadata on association success. A validated accepted orphan-membership recovery also restores the generic binding, even if local binding state was absent, while preserving the prior principal metadata because its Realignment command supplies no PAN bit. Generic parent matching, leave, realignment authority and broadcast reception consume the binding, while principal-specific conflict logic consumes macAssociatedPanCoord. Tentative PIB/channel/address preparation does not establish association. This requires no beacon cache or cross-request correlation.

The selected public-SET policy invalidates an existing binding when a successful SET actually changes PAN identity or either coordinator address, clearing principal metadata before its confirmation while retaining the newly configured value. An unchanged or rejected SET preserves binding. This prevents mutable configuration from silently rebinding an associated device to a different peer; subsequent SETs cannot resurrect the retired binding. Actual association and orphan-recovery commits use their existing internal owners and do not pass through this public-SET invalidation path. This is an explicit native state-lifetime policy, not an additional IEEE primitive field.

## GTS allocation timing and capacity

The allocation path uses typed characteristics/descriptors, codec views over the existing beacon bytes, a bounded value ledger and paired native GTS services. The ledger preserves grants independently of four-superframe advertisements and bounds the union of active and retained keys to seven, including old wire/owner binding reservations. It owns no radio timer. Outgoing characteristic values are range-checked, incoming reserved bits are ignored, and the request copies the existing security parameters. Supported allocation requests from devices tracking their associated PAN coordinator use the real CAP/ACK/beacon procedure; macGtsPermit controls coordinator admission. Missing context retains the native refusal in the service table above. Explicit native GTS DATA uses the matching copied physical reservation without CSMA; device/coordinator deallocation and activity expiry reuse the same removal/repacking operation. The [execution record](followup-results.md) separates representation preparation from operational behavior and its actual validation.

Clause 10.25.3/PDF384–385 starts the requesting device's descriptor wait at actual receipt of its GTS Request ACK. Table 10-121/PDF392–393 sets the duration to four superframes: four BI, with BI equal to 960×2^BO symbols under 10.2.2.1/PDF182–183. The ACK itself never establishes an allocation. A matching descriptor received at the native inclusive deadline can complete the request; expiry without one returns NO_DATA. Immediate coordinator decisions at command dispatch meet the separate decision bound.

The standard requires descriptor retention for four superframes but does not prescribe local skipped/failed-TX bookkeeping. The selected owner policy makes a new or replaced descriptor eligible at the next unconstructed beacon. Its first actual outgoing publication defines epoch n; retain it through n+3 and retire before constructing n+4. Construction or readiness refusal before first publication consumes no epoch. After publication, skipped or locally failed scheduled epochs advance the lifetime rather than restarting it. Existing outgoing epoch bookkeeping drives catch-up at the next boundary/admission, without a separate descriptor timer. Retain old owner/wire keys through retirement, and never age a replacement using an older in-flight snapshot. Positive descriptor expiry leaves its active grant intact.

An actual first beacon from an accepted replacement START is also an outgoing epoch. Repeated immediate same-PAN replacements cannot extend published records beyond four epochs. Keep prospective aging with the existing prepared-beacon candidate until actual RF commit, so a pre-RF replacement failure preserves the authoritative ledger and newly unpublished records do not age prematurely.

Charge each ordinary scheduled target once across PHY failure/restart. Catch-up uses the existing last-aged outgoing boundary; a suppressed duplicate does not count toward its four unaged-epoch bound. Four distinct unaged epochs exhaust every already-published record, while unpublished records remain eligible for their own first publication. No separate advertisement timer or historical binding store is required.

Retained identity reservations prevent a new allocation; they do not add EUI information to a received descriptor. Under 10.25.3, immediate short-address reuse by another member yields DENIED if it receives the matching old zero-start descriptor during its ACK-relative wait. Same-EUI/new-short rebinding receives no matching old descriptor and yields NO_DATA under the selected no-new-admission policy. Both retain the old reservation and require a later admitted retry for a new grant. No binding-history cache is used to override the wire result.

Figure 7-9/PDF88–89 and the macGtsPermit PIB description advertise coordinator acceptance; the audited requester procedure does not require a latest-TRUE local admission gate. The selected native policy permits a valid tracked upper request after FALSE: the closed coordinator ACKs without admitting a new decision, and the requester times out only if no matching descriptor arrives. Higher-layer policy may avoid that request. Separate tests distinguish this case from competing requests based on an earlier actual TRUE beacon.

For coordinator removal under 10.25.5/PDF386–387, preserve the original short address, length and direction in the descriptor and set its start to zero. The indication carries the deallocated characteristics with type zero (Table 10-120/PDF392). Snapshot the removed grant before erasing it so notifications retain those values. Device-requested deallocation has distinct advertisement behavior assigned to B3-04.

Clause10.25.5 explicitly uses MLME-GTS.request for higher-layer coordinator deallocation, but Table10-118/PDF391 supplies only characteristics and security parameters, with no device selector. Different members can have identical length/direction characteristics. The selected native mapping therefore adds an optional short-address target to that existing request for coordinator-initiated deallocation only. This is a model extension resolving the selector omission, not an IEEE wire field or an inferred first-match rule. The coordinator validates the target's current membership and matching grant before mutation. Device requests remain targetless and use their existing associated-parent context; coordinator allocation remains unsupported.

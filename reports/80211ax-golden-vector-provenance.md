# 802.11ax independent golden-vector provenance

The values below are transcribed from IEEE Std 802.11-2024 and are not
generated by the INET implementation. They are the review source for Gate 0
unit-test literals. The generated standards corpus was fresh when reviewed
(`80211ax-2024`, source hash prefix `c08beb0e16bf`).

## HE-SIG-B allocation-code boundaries

Source: Table 27-27. The fixture set must exercise at least these semantic
boundaries:

```text
valid:    0, 15, 16, 31, 96, 112, 113, 114, 115, 116, 127,
          128, 191, 192, 199, 200, 207, 208, 215
reserved: 216, 223, 224, 255
```

Code `0` is the 20 MHz partition containing nine single-user 26-tone RUs in
the order listed above.

## HE-LTF count mapping and model choice

Source: Clause 27.3.11.10 and Table 21-13.

| Per-RU NSTS requirement | Initial HE-LTF symbols |
|---:|---:|
| 1 | 1 |
| 2 | 2 |
| 3-4 | 4 |
| 5-6 | 6 |
| 7-8 | 8 |

For multi-RU HE MU, the standard derives the initial requirement independently
for each RU and uses the maximum. It permits a transmitted count in
`{1, 2, 4, 6, 8}` that is at least that maximum. INET's deterministic DL
policy chooses the minimum legal value. HE TB does not use that policy: the
Trigger Common Info field supplies the count and GI/LTF type.

## BSR ACI wire-boundary vectors

Sources: Figure 9-30 and Tables 9-32 and 9-33. INET's internal access-category
ordinal is BK=0, BE=1, VI=2, VO=3, whereas the IEEE ACI encoding is BE=0,
BK=1, VI=2, VO=3. Conversion at the wire boundary is therefore mandatory.

With scaling factor zero and both queue-size codes zero:

```text
TID 0 / AC_BE: ACI bitmap 0001, ACI High 0 -> word 0x0000004f -> 4f 00 00 00
TID 1 / AC_BK: ACI bitmap 0010, ACI High 1 -> word 0x0000108f -> 8f 10 00 00
```

These vectors are deliberately asymmetric in the internal and wire ordinals;
VI/VO-only vectors cannot detect a BE/BK swap.

## Decisive HE-SIG-B symbol-count vector

Sources: Clause 27.3.11.8, Tables 27-25 through 27-28, and Table 27-118.

Configuration:

- 20 MHz, uncompressed HE-SIG-B;
- allocation code `0`, nine one-stream 26-tone users;
- HE-SIG-B MCS 0, DCM disabled;
- deterministic zero padding.

Independent accounting:

```text
Common field:       8 allocation + 4 CRC + 6 tail = 18 bits
Four 2-user blocks: 4 * (2 * 21 user + 4 CRC + 6 tail) = 208 bits
One 1-user block:   21 user + 4 CRC + 6 tail = 31 bits
Unpadded total:     257 bits
NDBPS:              26 bits/symbol
Padding:            3 bits
Expected length:    10 OFDM symbols
```

This vector intentionally fails the old user-count-only estimator, which
returns nine symbols because it omits per-block CRC/tail and final padding.

## Annex Z byte oracle

Source: informative Annex Z, example 2. Integer fields are serialized LSB
first as specified by Clause 27.3.11.8.1.

```text
Content channel 1: a9 0d 53 b5 71 32 00
Content channel 2: ab 0d 54 01 00 00 00
```

These octets are an oracle for a complete represented HE-SIG-B content-channel
codec. Merely comparing the literals to themselves is not a conformance test.

## Individual TWT Setup action-body vector

Sources: Table 9-617 and Figures 9-790, 9-791, and 9-793. The frame body is
Category (22), Unprotected S1G Action (6), Dialog Token, and one TWT element.
For dialog token 19, request=1, setup command=2, trigger=1, implicit=0,
announced=1, flow ID=3, wake-interval exponent=4, target wake time 1,234,567,
nominal wake duration 8, wake-interval mantissa 6,250, and TWT Channel 7, the
independent little-endian body bytes are:

```text
16 06 13 d8 0f 20 95 11 87 d6 12 00 00 00 00 00 08 6a 18 07
```

The complete management frame is 44 octets: a 24-octet management header, a
3-octet action header, and a 17-octet TWT element. The current HE schema calls
the final Individual TWT Parameter Set octet `persistence`; on the wire this
octet is TWT Channel. Renaming/separating that model state is a Gate 1
wire-versus-model migration; the golden octets above already use the normative
wire interpretation.

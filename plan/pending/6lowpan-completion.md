## P8 implementation contract

`LowpanContextTable` stores at most 16 canonical IPv6 prefixes of lengths 0–128, absolute validity deadlines and a compression permission. `LowpanLayer` owns one table per interface and loads an optional XML `compressionContexts` parameter at initialization. Codec lookups take explicit simulation time; missing/expired contexts reject context-dependent decoding, while context-independent unspecified source and unused CID values preserve current behavior. The context identifier octet follows RFC 6282 section 3.1.2. Multicast context prefixes are limited to the 64-bit prefix field of the RFC 3306/3956 representation.

The owner exposes a typed context-install operation for future ND updates. Prefix/length replacement clears partial receive state and cancels its timer; validity/permission refresh does not reinterpret stored bytes. A FRAG1 decoded while its context is valid already contains the reconstructed IPv6 address, so later expiry cannot change that snapshot. FRAGN-first storage is invalidated by prefix replacement before a later first fragment can mix generations. Static configuration persists through ordinary lifecycle cleanup, with absolute validity continuing to run.

The affected source is restricted to unsealed `src/inet/linklayer/lowpan/` codecs, owner and NED configuration. Existing stateless calls retain defaults. Proposed direct verification: `LowpanStatefulContexts` unit and protocol cases, then existing `LowpanIphc*`, `LowpanNativeReassembly`, `LowpanNativeFragmentBoundaries` and the focused enabled/feature-off matrix. Packet ownership and first-fragment normalization retain the existing packet API; no sealed source is modified.

The selected multihop profile has one configured DAD authority per 6LR and allows an ordinary-interface-only 6LBR. Enabling this profile checks every requested address, including EUI-derived addresses for which RFC 6775 permits omitting this check. Initial and refreshed acknowledgements wait for confirmation or the selected fallback; an existing valid registration remains usable while its refresh is pending. Same-owner repeated requests coalesce without resetting the bounded DAR attempt count; another owner cannot replace a pending request. Tests distinguish this fallback from confirmed uniqueness. Zero-lifetime requests supersede pending positive requests and propagate removal to the authority; a late positive DAC cannot complete a zero-lifetime operation. Match authority, address, owner and operation lifetime before a DAC changes state, then calculate accepted deadlines from completion time. The 6LBR table never installs a native neighbor binding by itself.

DAR receive validation resolves the conflicting RFC 6775 sections 4.4 and 8.2.1 in favor of section 4.4's Code-ignore rule and RFC 8505 section 6.4's explicit legacy interoperability flow. Legacy transmission uses Code zero and an eight-byte owner; legacy reception accepts the compatible eight-byte extended form and ignores its transaction field. This choice does not claim conformance to section 8.2.1's contradictory literal Code-zero condition. P11 interprets the Code suffix and variable owner lengths explicitly; unknown extended suffixes are unsupported rather than assigned a guessed length.

Relay coalescing retains the original 20-second birth bound. A same-owner changed positive lifetime updates the copied operation/reply context without resetting attempts, retry time or birth; old-lifetime DACs cannot complete it. Zero removes only matching local state immediately and supersedes the positive operation once. It receives at most three zero-DAR attempts while keeping the original birth deadline, so one pending birth permits at most three positive plus three zero requests. Repeated zeros do not reset that budget, and positives received during a pending zero operation are ignored until removal completes. This is an explicit bounded-operation policy; it ensures a late cancellation can still reach the authority after the positive request budget is spent.

Before every DAR, and before delayed DAC/fallback completion, require the configured DAR source to remain a valid assigned non-link-local, non-loopback unicast address. This differs from an unreachable authority with valid local context, which still gets the bounded three-second success fallback. Syntax/role errors fail configuration; assigned-source validation occurs after address configuration, with the same predicate checked again at runtime. Tests invalidate source and reply target while pending and distinguish abandonment from genuine authority-outage fallback.

At a host, preflight the complete authority group after native envelope/M=0 validation and before associated PIO, SLAAC, context or information-refresh effects. Stale/rejected groups cannot alter those effects. Accepted context/prefix information is independent of registration backoff and candidate-default-router admission: in particular, an accepted C=0 or zero-lifetime update must retire the context even while address registration is blocked. Reuse inherited advertising-interface timers, self-message dispatch and cleanup for periodic native distribution RAs, overriding native authority-group packet construction rather than adding another periodic scheduler. Keep the existing bounded delayed unicast RS responses. Router authority groups are ND-wide and install effective contexts on all participating native interfaces before any downstream advertisement. Validate static/conflict constraints across that whole installation scope. Host groups remain ingress-interface scoped; ABRO-less host RAs perform individual CID updates, with no omission-based deletion of other CIDs.

The context-distribution profile reserves every statically configured CID, including expired static entries; learned advertisements must use disjoint CIDs. ND owns bounded per-authority snapshots and per-interface effective-CID ownership. Validate the complete update before changing accepted state. Reject a static overlap or incompatible prefix/length against another live authority atomically, with an observable conflict; expired groups cannot cause permanent rejection. This conflict policy is a selected model restriction, not an RFC-prescribed reconciliation algorithm. Separate source groups remain available for faithful relay, while the adaptation layer owns one effective context per CID.

Accepted matching-CID updates change the effective entry in arrival order: C=0 disables compression immediately, explicit zero removes immediately, and a later accepted C=1 may enable it again. Previously stored source groups never reactivate an entry automatically. Omission from a replacement snapshot, ABRO expiry and lifecycle cleanup remove an effective entry only while the affected authority still owns it; refresh uses current deadlines so an old timer cannot delete new state. An ABRO-less host update has a distinct owner identity. Forwarding stored information does not apply it locally again. These ownership and no-fallback rules are explicit policies around RFC 6775 sections 5.4.2, 6.3 and 8.1.4; they avoid interpreting the unspecified multi-authority selection procedure as maximum-C=1 aggregation.

For each positive 6CO, compression ends at the received lifetime deadline and decoding ends after twice the sampled advertising RA Router Lifetime, capped by the owning ABRO expiry when present. Zero Router Lifetime adds no grace. C=0 retains decoding for its positive lifetime/grace; explicit zero and ABRO expiry remove immediately. Same-prefix deadline/permission changes and removal preserve already decoded FRAG1 snapshots; a new context-dependent FRAG1 fails once its context is absent. Prefix/length replacement keeps the existing partial-reassembly invalidation, including FRAGN-first storage. Static state survives learned-state cleanup. Tests schedule exact-deadline probes before and after timer priority.

ABRO versions use the literal unsigned 32-bit comparison of RFC 6775 section 8.1.3: lower versions are ignored and equal/newer versions update, without an invented wrap comparator. A relay forwards the ABRO unmodified as section 6.3 specifies while retaining its own absolute expiry; only PIO/6CO lifetimes decrease. Consequently an unchanged ABRO can give a downstream receiver a later local expiry; the documentation must identify that consequence. Positive 6CO remainders below one minute are omitted rather than encoded as explicit zero. Authority zero retains its specified 10000-minute meaning. Multi-authority tests distinguish C=0/zero arrival, owner-guarded omission/expiry, later received C=1, static conflicts and faithful separate RA groups.

## P11 transaction-order policy

Today a long-ROVR updated peer cannot establish an ordered registration through the legacy-only owners. Literal updated NS/EARO input must instead bootstrap LL state, register a different global target through a routed authority, receive correlated replies and retain usable data reachability through equal parallel attachment and newer movement. Direct cases cover all four ROVR widths, source/target status precedence, full versus projected authority identity, legacy downgrade, exact expiry/removal, comparator boundaries, bounded capacity, stale notifications, R=0/R=1 route behavior, capability readiness, malformed input and lifecycle cleanup. Stage two depends on this complete receiver path; its new fixture must drive actual automatic hosts rather than substituting literal peers.

The same behavior commit also includes independently authored `LowpanExtendedRegistrationRaces.test` and `extended-registration-races.md`. Source retry windows, bounded RTO/backoff, oldest-missing-first recovery after the initial send, ECN echo and short completed-datagram retention are owned state. FULL means `0xffffffff`, including unused bitmap bits; NULL aborts. Receive completion requires byte coverage and delivery exactly once. Preserve the first-fragment reconstructed address snapshot through context expiry, without changing compressed coverage coordinates. Loss-injection fixtures must disable or exhaust local MAC retry for the selected lost frame so an observed retransmission establishes end-to-end recovery rather than only MAC recovery.

The selected recoverable compression profile uses contextless outer-only IPHC with Next Header inline at the source and every relay. Extension, UDP and nested IPv6 bytes remain unchanged raw tail bytes; ordinary P9 NHC behavior is independent. Reject context-dependent or NHC-compressed input outside this recovery profile. For fixed Traffic Class/Flow Label, each stateless link-local address can expand by at most eight bytes and Hop Limit by one, so source-to-any-hop growth is at most 17 bytes in total. Global addresses remain fully inline. This conservative codec bound does not authorize forwarding scope-invalid link-local packets. The encoded outer header is 3–40 bytes; no reconstructed tail header must fit wholly in the first fragment.

Let `P` be the declared minimum path adaptation payload, `S` the selected subsequent-fragment data size and `H` the source encoded outer-header size. The first data size has maximum `min(S, P - 6 - 17)`, requiring the complete `H`, configured minimum fragment size and positive progress to fit before emission. For `P=94` and `S=80`, that maximum is 71 bytes; if the declared path minimum and actual local envelope are both at least 104, `S=80` permits an 80-byte first data fragment. Select a feasible partition of no more than 32 sequence identities: every source fragment, including the final one, respects the configured minimum and maximum, and the first contains `H`. Rebalance a short tail, reducing the first size within its bounds if needed; reject infeasible partitions before tag allocation or emission. There is no short-final-fragment exception. RFC 8931 section 7 explicitly scopes these configuration settings to the fragmenting endpoint. A relay's recompressed first fragment may exceed the source maximum or fall below its minimum; validate its complete prefix, wire width and path/local payload envelope instead. Validate the actual local native envelope independently of the declared remote path assumption and require representable 16-bit compressed size/offsets. A relay replaces its incoming outer header `Hi` with `Ho`, preserves raw tail and sequence, changes first size/total size by `Ho-Hi` and applies that delta to subsequent offsets. Decode original IPv6 length as `compressedSize - Hi + 40`; the codec must never receive compressed total size as its original-size argument. Freeze encoding/delta for retries. Literal units and live forwarding must prove source partition boundaries, header expansion, corrected IPv6 payload length, raw extension/UDP/nested tails, prefix/path-budget refusal and sequence limits before this profile is considered implemented.

Select a native unicast recovery deployment with at most eight declared forwarding hops, minimum path adaptation payload 94 bytes and 50 ms ingress-to-next-receive residence at each hop. Data spacing is 150 ms after the preceding lower completion; ACK controls have no data-spacing wait but retain the ingress deadline. Source operation lasts at most 45 s from admission, enforced by its own timer independently of outstanding lower callbacks. Default subsequent data size is 80 bytes, configured minimum 48 and maximum 80; validate configured maximum below 512 and actual sequence/prefix fit. Default window is 32, configurable from 1 to 32. Expected RTT is bounded by the declared successful-delivery profile at 800 ms; minimum RTO is 850 ms, initial 2.4 s, exponential factor two and maximum 9.6 s. Validate actual effective clock durations and RTO ordering. These declared remote path limits require compatible simulation configuration and actual loss-free eight-hop proof; they are not discovered from Hop Limit or topology automatically. Mesh composition, alternate-path rebuilding, datagram restarts, PMTU splitting, delayed/unsolicited ACK and source ECN adaptation are outside this profile. Receiver ECN echo remains required.

The source uses fixed ascending batches of at most its window size and one lower original at a time. Offer every sequence initially before ordered missing-sequence repair rounds. Partial ACKs supply only monotonic positive receipt evidence; stale zeros cannot create window credit. Timeout can classify unconfirmed batch members as lost, while an explicit X-timeout probe can repeat the current X sequence before the initial round finishes. All source submissions share a cumulative initial-plus-three-repeat budget per sequence, including probes, queue refusal and MAC failure. Arm X RTO after either terminal lower outcome; partial/duplicate ACK cannot refresh it or the operation deadline. FULL succeeds only after every actual sequence was attempted and accepts its required unused one-bits; a partial bitmap containing all used bits waits for FULL. NULL aborts. ACKs with impossible unused/never-attempted positive bits are ignored, with FULL's explicit exception. Freeze interface/PAN/native-peer/tag correlation; no wire attempt number or ACK freshness guarantee is invented.

Incomplete recovery expires at first admission plus 60 s. Completed receivers and relays retain FULL response behavior for 30 s, then abort-only identity history until the original first-admission-plus-120-s ceiling. Failure and lifecycle cleanup retain that same absolute ceiling without refreshing it. Reserve each source/swapped eight-bit recovery tag for at least 166 s from allocation: 45 s operation plus 0.4 s forward residence plus 120 s history plus 0.4 s reverse allowance is 165.8 s. Use one coordinated recovery tag pool per egress namespace, separate from the different RFC 4944 wire identity. The 50 ms delivery bound does not bound a queued original's terminal callback latency. Consequently, 30 s FULL retention is a selected finite policy rather than a guarantee of recovery under arbitrary queueing or repeated ACK loss; the independent operation deadline still terminates the source and late callbacks remain inert. No 6.4-second initial-round bound is claimed for windows that wait for ACKs. Deterministic cases must cover windows 1/2/32, failed-X RTO, first-fragment/orphan NULL, stale/unsent-bit ACKs, initial-before-repair order, FULL loss/retention, exact-deadline/lifecycle cancellation and actual selective retransmission beyond MAC retry.

Recovery activation is default-off and requires native support, IPHC and no Mesh. P14 forwarding and pacing may coexist through separate wire identities and completion correlation. Only positively classified non-ND unicast data that would otherwise need fragmentation enters recovery; unclassifiable source input, unfragmented packets, broadcast and all seven ND/control types retain their ordinary paths. Incomplete chains and nonfirst IPv6 fragments must not become eligible merely because a control classifier cannot identify their type. Failed recovery admission drops observably. A local destination fully recovers the compressed stream and then enters normal IPv6 processing. Transit requires actual forwarding permission, valid scope, live route/native binding, source usability and the established policy-hook predicate. Processing-bearing or unclassifiable first-fragment chains and unsupported hooks or egress produce NULL and fixed abort protection. Transit original length `D - H + 40` must fit the selected egress IPv6 MTU before output; oversized input receives NULL/protection and a safe ICMPv6 Packet Too Big quoting the actual egress MTU. Revalidate the MTU during frozen-path continuation and cancel if it changes incompatibly. Preserve local receiver wire/resource limits separately. Do not feed compressed recovery coordinates to ordinary RFC 4944 reassembly or bypass required IPv6 processing.

Each Layer's recovery coordinator bounds active source, receiver, relay and retained-history records together at 64, without live eviction. Source originals, reserved receiver bytes and queued relay data share a 32768-byte cap. A relay record queues at most four frames and 512 data bytes. At most 64 pending ACK/reset controls are admitted; overflow drops observably without evicting identity protection. Each egress owns its coordinated 256-tag pool and at most 256 reverse bindings containing copied owner module/token identities. Add an internal completion-kind discriminator so recovery cannot consume paced-source or P14 completion. Register copied identities before pushing, detach state before observations and never access an original after transfer. Interface cancellation and down-state expiry preserve fixed tag/history guards.

For reset packets with offset zero, a usable VRB and reachable next hop select the frozen path regardless of Sequence. Otherwise sequence zero attempts stateless cleanup routing using a complete supported IPv6 header, conserving no new operation or reverse mapping; its outgoing tag guard may remain to prevent collision. If that header is absent or unusable, return NULL when X is set and otherwise discard observably. A nonzero sequence with no usable VRB is discarded with NULL regardless of X. A header-bearing reset can carry routing bytes even when Fragment_Size is zero; normal data-size equality must not make the specified cleanup attempt impossible. Known-path no-X reset releases reverse state; X retains only bounded NULL-response correlation. Reset and cleanup never renew original history anchors or deliver a datagram.

## Progress

P10/P11 use RFC 6775 and RFC 8505 individual unicast-address registration, including the RFC 8505 base-peer compatibility flow. Later updates are explicitly outside this package: RFC 8928 cryptographic AP-ND, RFC 8929 backbone federation, RFC 9010 RPL signaling, RFC 9685 multicast/anycast subscriptions and RFC 9926 prefix registration. ROVR comparison is an ownership identifier match, not cryptographic proof. The generic ICMPv6 wire prerequisite precedes native registration policy; it preserves variable-length options and decodes DAR/DAC subclasses without a dependency on the optional LoWPAN feature.

P10/P11 first add the separately reviewable generic ICMPv6 wire prerequisite: `Ipv6DuplicateAddressHeader` supports DAR/DAC and extended 8/16/24/32-byte ROVRs through the ordinary ICMPv6 serializer and `Ipv6NdMessage` dispatch. Raw ND options, including variable-sized link-layer addresses, retain their bytes without optional LoWPAN dependencies; existing eight-byte Ethernet options remain typed. Proposed direct coverage is `tests/unit/Ipv6NdRegistrationWire.test`, selected by `opp_run_unit_tests --load . -p inet -m debug --no-build -f 'Ipv6NdRegistrationWire\.test$'` after a fresh debug build. Ordinary ND safely drops unsupported registration messages and address representations; `Ipv6NdUnsupportedRegistration.test` checks the ordinary IPv6-to-ND receive path. This prerequisite does not claim registration policy or live native ND integration.

P9 is split into a wire-representation/nested-IID preparation commit with `LowpanExtensionNhcWire` unit vectors, a chain-codec commit with independent chain vectors, and production integration with `LowpanExtensionNhc.test` and its reviewer document. Preparation does not claim live extension compression before the production caller is connected.

P9 runtime regression exposed a shared IPv6 prerequisite: local delivery stored a decoded Fragment header's raw pointer after its scan-local owning chunk was destroyed. Preserve a shared chunk reference through reassembly in a separate `ipv6: fix:` commit, verified by literal serialized fragments and the affected route-over/source-fragmentation cases, before enabling NHC reconstruction.

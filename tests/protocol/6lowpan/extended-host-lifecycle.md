This fixture exercises the automatic updated-host consumer with real native
RS/RA/NS/NA exchanges and ordinary return data. It supplements the main
`LowpanExtendedHostRegistration.test` width, parallel-registrar, legacy and
capability/status matrix. The bounded campaign is General runs 0–4, seed 0.

## Composition and boundaries

```mermaid
flowchart LR
    H[Real automatic updated host] <-->|Native MAC/radio| R[Real updated registrar]
    R <-->|Ordinary Ethernet / run 3 only| A[Silent authority]
```

The host and registrar use their production IPv6/ND/adaptation/MAC/radio modules.
The domain config contains peer identities, with no learned-neighbor entries.
There is no PIO: the public interface API assigns manual global A, while ordinary
initialization supplies its LL address. Thus two distinct history keys suffice.
The configured 128-bit default ROVR is intentionally unrelated to either address
or native peer identity. The registrar advertises actual extended capability.

The checker observes actual outgoing host requests, registrar native reception,
wire NA arrival and the host's accepted-registration signal. Address assignment
and removal use `Ipv6InterfaceData`; whole-node STOP/START uses the public
`LifecycleController`/module operations and actual `NodeStatus` transitions.
No private helper or registration-table mutation is used. Data is an ICMP echo
exchange with two independently checked payload bytes, including its real return
through the learned registrar `/128`, without requiring the UDP transport feature.

Run 3 uses a real routed DAR to the silent Ethernet authority to hold global work
pending. The LL address is removed and the same literal re-added as tentative:
it remains an IPv6-local destination, but cannot supply a valid registration
source. A copied, independently checksummed late NA enters the registrar's
ordinary IPv6 transport entry with explicit native interface/L2 and Hop Limit
requests, then crosses its adaptation/MAC/radio. A fixture-only built-in
zero-delay channel observes the sole
direct host `IPv6.ndOut` → `ND.ipv6In` connection using its existing `messageSent`
signal. The checker verifies those exact endpoints and the borrowed signal
payload; it does not buffer packets, change tags or drive protocol actions from
that observer. This proves actual ND-ingress arrival rather than accepting an
upstream destination drop as evidence. Post-delivery observations require the
source to remain tentative and global registration unusable.

Run 4's adverse Moved NAs also use real MAC/radio delivery. They copy the actual
observed transactions and clear the unsolicited NA's S flag. The stale and
matching-current inputs distinguish safe correlation from ignoring every Moved.
These literal adverse inputs do not claim that the production registrar emitted
those particular notifications. Other exchanges are generated by actual hosts
and registrars.

## Cases

| Run | Trigger | Required production observations |

| 1 | Re-add A as soon as the real registrar receives zero 241, before its reply returns. | Positive 242 waits until zero-reply observation; same-time ordered processing is allowed. It retains identity/history and restores real data. |
| 2 | Stop the actual host after initial A service, then start it again. | DOWN observation has no owned default route or learned router binding, while history remains two. | 3 | After the actual global DAR reaches the authority, remove its LL source and re-add it as tentative; deliver a valid matching late NA. | Its frozen tuple reaches the sole host ND ingress. No replacement-source NS or successful global acceptance appears, including through the former retry/fallback interval. History persists; the source remains tentative and unusable. |
| 4 | A real periodic refresh accepts global 241. Deliver stale unsolicited Moved 240, exchange data, then deliver matching-current Moved 241. | Stale 240 preserves current service and data. The matching-current positive control retires ordinary source use while preserving LL service/history before bounded rediscovery; it does not demand permanent rejection or prevent later legitimate registration. |

Default refresh timing is retained except run 4, which uses fraction 0.05 to make
the real one-minute registration refresh after three seconds. Actions follow
observed protocol events rather than guessed initial discovery times. A 25-second
watchdog fails missing observations. This is a deterministic state/timing claim,
not a statistical or multi-seed robustness claim.

## Execution

Focused reproduction after a matching fresh library:

```sh
opp_run_protocol_tests --load . -p inet -m debug --no-build \
  -w '^tests/protocol/6lowpan$' -f 'LowpanExtendedHostLifecycle\.test$'
```

The first coordinated debug attempt compiled the fixture, then stopped in run 0
at router ICMPv6, time 1.113062419954 seconds/event 327. The initial header-only
Echo Request left no data after `Icmpv6` popped its header; its existing responder
then called `peekData()` on the empty remainder. The fixture now supplies two
payload bytes and checks their exact echo. This avoids the unrelated empty-echo
consumer path without changing generic ICMPv6 or packet code. The preserved
attempt is under `.codex-artifacts/lowpan-p11-host-20261116/attempt3/` outside the
repository (`lifecycle.out` and `lifecycle.err`).

The next attempt passed runs 0/1, then stopped at the run-2 down probe, time
1.068030419954 seconds/event 233. Generic STOP clears interface protocol tags;
the checker's unconditional address-data getter therefore threw before reaching
its route/binding/history assertions. The checker now uses a nullable lookup for
down/start observations and fetches re-created address data after startup. It
still requires all transient-state cleanup and retained-history observations,
and publicly reassigns manual A when generic lifecycle removed it. That attempt
is preserved in the same artifact root's `attempt4/lifecycle.out` and `.err`.

The following attempt passed runs 0–2, then reached a connected-NIC-gate
`sendDirect` error in run 3, time 1.429534729954 seconds/event 195. The literal
NA helper now uses the registrar's existing IPv6 transport path with explicit
native requests, rather than targeting its connected NIC input. This preserves
real MAC transmission and the ND-ingress observer. Its failed setup is retained
as `attempt5/lifecycle.out` and `.err`.
